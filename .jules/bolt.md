## 2025-05-10 - Batch Unpacking and Direct Tuple CSV Output for Binary Scanners
**Learning:** Calling `struct.unpack_from("<I")` per word in Python creates massive function call overhead when scanning multi-megabyte binary files (e.g. 4+ million iterations). Additionally, `csv.DictWriter` allocates dictionaries and performs dict lookups for every candidate row, and generator expressions in range checks (`any(...)`) allocate generator frames. Batch unpacking words in 64K-word chunks (`struct.unpack_from(f"<{n}I")`), using standard `csv.writer` with tuples, and using direct loops for range checks reduces scanning time by ~50%.
**Action:** When scanning or parsing binary files in Python, batch unpack words into tuples, use direct tuple rows with `csv.writer`, and avoid generator allocations inside hot loop predicates.

## 2025-05-11 - UTF-8-SIG Output File Encoder Overhead in CSV Output Streams
**Learning:** Opening output files with `encoding="utf-8-sig"` wraps every string written to the stream in Python's `utf_8_sig.IncrementalEncoder` wrapper to verify whether a BOM was already emitted. When processing hundreds of thousands of CSV rows, this wrapper overhead incurs millions of unnecessary Python function calls. Opening the file with `encoding="utf-8"` and writing `"\ufeff"` once at initialization produces byte-for-byte identical output while using C-level UTF-8 encoding directly, reducing overall script execution time by ~50%.
**Action:** For large file output streams requiring a UTF-8 BOM signature, open with `encoding="utf-8"` and explicitly write `"\ufeff"` once at stream start instead of using `encoding="utf-8-sig"`.
